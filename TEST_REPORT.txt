Persistence and database validation:

- A prior synthetic consultation was recovered after two deliberate redeploys,

- The v0.5 production flow completed against PostgreSQL and /health reported
  database=ok before and after the test.
- The synthetic consultation used for this validation was deleted at the end.
- A separate read-only connection through the external Render endpoint could not
  be established because that endpoint closed the TLS session. Render's own MCP
  query showed the same limitation. This did not affect the service's private
  PostgreSQL connection, but direct database observability remains an open
  operations item.

Root cause and resolution:

- The original repository and Render service were disconnected.
- The original SQLite database used an ephemeral free-service filesystem.
- Safety patches discussed in chat were not permanently encoded or regression-tested.
- The old contract did not enforce explicit data classification, provenance,
  complete safety review, retention or privacy-safe metrics.
- FastAPI startup and port binding were normalized for Render using $PORT.
- PostgreSQL persistence, fail-closed production configuration, API-key
  authentication, request limits and sanitized validation errors were implemented.
- All 12 Safety Gate flags are mandatory; missing data no longer means normal.
- Baseline and post-intervention neurovascular checks, pediatric review and urgent
  response documentation now block finalization when required.
- Reported information cannot be stored as a physical finding, and AI suggestions
  cannot arrive prevalidated.
- The static GPT Action schema is generated from and tested against the application.

Current limitations and release boundary:

- The free PostgreSQL database expires on 2026-09-26 and has no backups or PITR.
- One global API key does not provide individual identity, RBAC or per-user revocation.
- Each Action call can still require explicit user permission in ChatGPT because
  persistent "always allow" access was intentionally not enabled.
- The 50 automated cases still require signed human clinical review.
- Legal, privacy/DPO and institutional owners remain to be formally named.
- Identifier detection is defense in depth, not proof of anonymization.
- The evidence endpoint remains a metadata-only placeholder; no medical RAG or
  vector store is connected.
- The free web service can cold-start after inactivity.
- Docker was hardened for non-root execution, but the image was not built locally
  because Docker is not installed on this machine.

Decision:

- Engineering status: READY FOR SYNTHETIC INTERNAL ALPHA.
- Clinical-production status: NOT AUTHORIZED.
- Next mandatory actions: obtain signed human clinical review of the 50 scenarios,
  name the governance owners, and replace or migrate the expiring free database
  before any expansion beyond the synthetic internal alpha.
