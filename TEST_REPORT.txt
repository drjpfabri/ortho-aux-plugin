Persistence proof:

- A synthetic consultation was created in PostgreSQL with one non-patient test fact.
- The web service was deliberately redeployed twice.
- The same consultation ID and fact were recovered after both redeploys.
- This confirms that consultation state no longer depends on the ephemeral web-service filesystem.

Root cause and resolution:

- The original repository and Render service were disconnected.
- The original SQLite database lived on an ephemeral free-service filesystem.
- FastAPI startup and port binding were normalized for Render using $PORT.
- SQLAlchemy now supports PostgreSQL in production and SQLite for local development.
- Authentication, OpenAPI metadata, health checks, consultation workflow and clinical safety blockers were implemented and tested.
- The GPT Action schema points to the production HTTPS server.

Current limitations and safety boundary:

- The free PostgreSQL database expires on 2026-09-26 and has no backups.
- The free web service can cold-start after inactivity.
- Do not store identifiable patient data on this evaluation infrastructure.
- Before clinical production, use a paid database with backup/PITR and complete LGPD, security, retention and institutional governance review.
- The evidence endpoint remains a metadata-only placeholder; the medical RAG/vector store is not connected.
- Docker was hardened for non-root execution, but the image was not built locally because Docker is not installed.
